# 계산·확인 상태·필터 기준

## 확인된 값과 미확인 값

저장하는 수치는 공식 원문에서 읽은 값입니다. 미확인 값은 현재 카드 스키마에서 필드를 생략합니다.
추출 중간 단계의 `null`이나 누락값을 0 또는 `false`로 바꿔 넣지 않습니다.

- `annual_fee_krw: 0`은 연회비가 없다고 확인한 경우입니다.
- 실적 구간이 비어 있다는 사실만으로 무실적 카드가 되지 않습니다. 별도 근거가 있어야 `no_prev_month_spend_condition: true`를 둡니다.
- `tax.counts_as_spend`는 세금 납부액의 전월실적 포함 여부입니다.
- `tax.earns_rewards`는 세금 납부가 적립·할인 대상인지 여부입니다. 실적에 포함돼도 적립·할인은 제외될 수 있습니다.
- 두 세금 필드는 각각 `true`·`false`·미기재를 구분합니다. 제외 문구를 못 찾았다는 이유로 `true`를 채우지 않습니다.

현재 세금 스키마의 두 boolean만으로 국세·지방세·납부 채널별 모든 차이를 표현할 수는 없습니다.
명확한 범위의 근거만 입력하고 제한·예외를 `tax.note`에 남깁니다. 적용 범위를 확정할 수 없으면 미확인으로 둡니다.
세금 납부 기간 행사는 상품의 상시 세금 조건에 병합하지 않고 별도 행사 데이터로 관리합니다.

## 날짜와 검수 상태

| 필드·표시 | 의미 |
| --- | --- |
| `generated_at` | 데이터 파일 또는 보고서가 생성된 날짜·시각 |
| `updated_at` | 해당 카드 레코드의 갱신일 |
| `source.retrieved_at` | 실제 공식 원문을 읽은 날짜 |
| 30일 이내 확인 | 한국 날짜 기준 원문 수집 후 30일 이하 |
| 재확인 필요 | 원문 수집 후 30일 초과 |
| 확인일 미확인 | 날짜 없음·잘못된 날짜·미래 날짜 |

30일 기준은 화면에서 오래된 자료를 찾기 위한 운영 기준이며 상품의 유효기간이 아닙니다.
오늘 HTML을 읽었어도 현재 발급 가능성이나 조건 전체를 확인하지 못했을 수 있습니다.
오래된 자료를 유지한 카드에 새 수집일을 붙이지 않습니다. 캐시 재사용 때도 원래 수집 시각을 보존합니다.

`review_status`는 추출 방식과 사람 검수를 구분합니다.
자동 추출 결과는 `machine_extracted`, 사람이 공식 원문을 대조한 결과는 `human_reviewed`입니다.
네트워크 성공·스키마 검증·회귀 테스트 통과만으로 사람 검수 상태를 올리지 않습니다.

`confidence`는 추출된 정보의 충실도입니다. 혜택의 법적 보장이나 최신성 점수가 아닙니다.
기존 피드·렌더링 파서는 연회비, 혜택 항목, 실적 조건, 요율, 한도의 확인 정도로 `high`·`medium`·`low`를 산정합니다.
세부 산정 규칙은 각 카드사 파서에 있으며 새 파서의 충실도도 원문 검수와 별도로 표시합니다.

## 수집 성공과 정본 반영

공식 페이지 접근 성공과 상품 데이터 검증 통과는 다릅니다.
HTTP 응답을 받았어도 오류 페이지·미치환 템플릿·빈 혜택·상품 식별 불일치·기존 핵심 정보 손실이 있으면 후보를 거절할 수 있습니다.

공통 수집기는 기존 카드의 연회비·통합 한도·실적 조건 등 주요 값이 사라지거나 혜택 수가 크게 줄어드는 경우를 검사합니다.
이는 추출 퇴행을 줄이기 위한 방어 장치이며 **정상적인 혜택 변경도 보류할 수 있습니다**.
거절된 후보는 공식 원문을 추가로 확인해야 하며, 기존 값이 여전히 현행이라는 뜻은 아닙니다.

보고서의 성공 건수는 자동 검증을 통과한 후보 수입니다. 이전 유지 건수는 갱신되지 않은 저장 카드 수입니다.
자료를 못 얻은 카드사를 상품이 없는 카드사로 취급하지 않습니다. 실행 보고서가 없으면 이번 수집의 성공·실패는 미확인입니다.
SHA-256은 수집한 원문 바이트의 추적값이며 내용 정확성 점수가 아닙니다.

## 피킹률

```text
피킹률(%) = 월 추정 최대 혜택 ÷ 전월 이용실적 기준 금액 × 100
```

구현은 [`site/picking.js`](../site/picking.js)의 `computePickingRate`입니다.
피킹률은 데이터에 저장하지 않고 화면에서 계산합니다.

### 분자와 분모

분자는 카드 전체의 `integrated_monthly_cap_krw`가 확인되면 그 값을 사용합니다.
없으면 각 혜택의 `monthly_cap_krw`를 합합니다. 원화 한도가 없고 `monthly_cap_points`만 있으면
계산에서만 **1포인트 = 1원**을 가정해 더합니다. 한도를 읽지 못한 혜택은 합계에 0으로 기여하지만 원본 데이터를 0으로 바꾸지는 않습니다.

분모는 양수인 `prev_month_spend_tiers_krw` 중 가장 낮은 구간입니다.
`basis`는 `integrated_cap`, `summed_benefit_caps`, `summed_caps_with_points` 중 사용한 방식을 알립니다.
통합 월 한도를 알고 있을 때 개별 혜택 한도를 다시 합하지 않습니다.

포인트의 실제 사용 가치는 사용처·교환 방식에 따라 다를 수 있습니다.
원본은 `monthly_cap_points`로 보존하며 환산 원화를 저장하지 않습니다.
계산 결과의 `usesPointAssumption`과 화면의 계산 설명에 이 가정을 표시합니다.

### 산출하지 않는 경우

| 상태 | 조건 | 화면 |
| --- | --- | --- |
| `ok` | 양수 실적 구간과 통합 한도 또는 개별 한도가 확인됨 | 피킹률 약 N% |
| `no_spend_condition` | 실적 조건 없음이 확인돼 분모를 정할 수 없음 | 실적 조건 없음 |
| `insufficient_data` | 실적 구간 또는 계산할 한도가 미확인 | 피킹률 산출 불가 |

분모를 임의로 만들거나 미확인 카드를 0%로 순위 매기지 않습니다.

### 추정치의 한계

모든 월 한도를 채웠다는 가정입니다. 이용자의 지출 패턴, 최소 결제액, 제외 가맹점,
혜택별 실적 구간과 등록 조건을 모두 충족하는지 계산하는 시뮬레이터는 아닙니다.
개별 혜택별로 더 높은 실적이 필요하거나 확인하지 못한 통합 한도가 있으면 과대추정될 수 있습니다.
연회비·세금 납부 수수료를 빼서 순절감액을 구하는 계산도 아닙니다.

반대로 한도가 미확인인 혜택을 합계에서 제외하므로 과소추정될 수 있습니다.
따라서 계산값 전체를 항상 보수적인 하한이나 실제 달성 가능한 상한이라고 보장하지 않습니다.
화면의 `pickingCaveat`에 계산 근거·포인트 환산·한도 미확인 건수를 표시합니다.

범위로 표기된 요율(`3%~10%`)의 최대값은 표시용입니다. 가정 결제액을 곱해 피킹률 분자를 만들지 않습니다.
`할인 대상 이용금액 한도`는 `월 할인액 한도`와 다르므로 같은 값으로 넣지 않습니다.

## 필터 정의

각 필터는 AND로 결합됩니다. 혜택 분야 안의 복수 선택은 OR입니다.

| 필터 | 동작 |
| --- | --- |
| 검색 | 카드명·카드사 이름·카드 종류·소개 문구·혜택 제목/설명에서 공백으로 나눈 모든 단어를 부분 문자열로 대조. 대소문자 무시 |
| 카드사 | `issuer` 완전 일치. 미수록 카드사도 저장 0장으로 표시 |
| 카드 종류 | 신용·체크 `card_type` 완전 일치 |
| 연회비 상한 | 확인된 `annual_fee_krw`가 선택값 이하. 미확인 카드는 제외 |
| 전월실적 상한 | 확인된 최저 구간이 선택값 이하 또는 조건 없음이 확인됨. 미확인 카드는 제외 |
| 세금 전월실적 | 포함 확인·제외 확인·미확인을 각각 구분 |
| 세금 적립·할인 | 대상 확인·제외 확인·미확인을 각각 구분 |
| 자료 확인일 | 30일 이내·30일 초과·날짜 미확인 |
| 원문 검수 | 자동 추출·사람 검수 상태 |
| 혜택 분야 | 선택한 분야를 하나라도 가진 카드 |

결과 0장은 저장 자료에서 조건이 확인된 카드가 없다는 뜻입니다. 시장 전체에 그 조건의 카드가 없다는 뜻은 아닙니다.
연회비·실적 상한 필터가 미확인을 제외하는 것은 알 수 없는 값을 무료나 무실적으로 오인하지 않기 위한 동작입니다.
초기화는 검색·필터·정렬을 기본값으로 되돌립니다.

## 기간 행사 표시

`card-events.json`의 `starts_at`, `ends_at`을 현재 한국 날짜와 대조합니다.
시작일과 종료일은 포함하고, 아직 시작하지 않은 행사·종료된 행사·기간이 불명확한 행사는 현재 목록에서 분리합니다.
표시 기준은 저장된 행사 기간이며 실시간 행사 상태 확인은 아닙니다.

조건 목록은 생략하지 않습니다. 카드사 단위 행사라는 이유만으로 해당 카드사의 모든 카드에 적용되는 혜택으로 연결하지 않습니다.
납부 채널·제외 카드·신청 여부·금액 조건·고객 부담 회차는 공식 행사 원문과 함께 확인해야 합니다.

## 카테고리 분류

기존 피드 파서는 혜택 제목·설명을 키워드 규칙으로 분류합니다.
여러 업종이 섞이면 텍스트에서 먼저 확인된 분야를 선택하고, 맞는 규칙이 없으면 `other`로 둡니다.
자동 분류는 상품 조건의 법적 범위가 아니며 상세 근거를 대신하지 않습니다.
