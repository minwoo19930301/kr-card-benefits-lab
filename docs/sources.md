# 공식 출처와 수집 방식

## 출처 기준

카드사 공식 공개 상품 페이지·공개 피드·상품설명서·공식 행사 공지를 사용합니다.
`data/issuers.json`의 `allowed_domains`가 카드 데이터의 도메인 검증 기준입니다.
외부 카드 비교 서비스·가계부 앱의 내부 API, 그 데이터의 이름만 바꾼 재가공본, 제3자 이미지 CDN 미러는 포함하지 않습니다.
검색 결과는 공식 URL을 찾는 데 쓸 수 있지만 검색 스니펫을 상품 조건의 근거로 저장하지 않습니다.

Bright Data를 사용해도 출처는 Bright Data가 아니라 **실제로 읽은 카드사의 공식 URL**입니다.
HTTP 200, HTML 다운로드, 유효한 JSON 스키마는 각각 전송·형식 검사일 뿐 내용의 정확성이나 이용 권한을 증명하지 않습니다.
상품과 무관한 오류 화면, 미치환 템플릿, 잘린 금액, 적용 범위가 모호한 조건은 미확인으로 처리합니다.

## 공통 공식 자료 수집기

진입점은 [`scripts/collect-official-bd.mjs`](../scripts/collect-official-bd.mjs)입니다.
파일명과 달리 `--transport brightdata`와 `--transport direct`를 명시적으로 구분합니다.

1. 기존 카드의 `source.url`과 `data/official-seeds.json`의 추가 공식 URL을 모읍니다.
2. 카드사 등록 도메인과 HTTPS 여부를 검사하고 중복 URL을 줄입니다. 제한된 실행에서 한 카드사만 차지하지 않도록 카드사별로 순회합니다.
3. 선택한 전송 방식으로 원문을 읽습니다. 수집일·응답 해시·크기와 시도 결과를 남깁니다.
4. 카드사별 파서로 혜택을 추출하고 스키마·공식 출처·제품 식별·기존 데이터 대비 정보 손실을 검사합니다.
5. 통과한 후보만 병합합니다. 실패·거절·미시도 카드는 이전 데이터와 이전 수집일을 유지합니다.
6. 후보 데이터와 보고서를 준비하고, `--apply`가 있으면 정본에 반영합니다. 반영 전 검증은 사람의 원문 검수와 다릅니다.

### 전송 방식

| 방식 | 준비 | 한계와 기록 |
| --- | --- | --- |
| `brightdata` | `BRIGHT_DATA_API_KEY`, 이미 생성된 `BRIGHT_DATA_ZONE` | Web Unlocker로 공식 공개 원문을 요청합니다. 사용량이 발생하며 키·권한·할당량 오류를 수집 성공으로 기록하지 않습니다. |
| `direct` | Bright Data 자격 증명 불필요 | 카드사에 직접 HTTP 요청합니다. 스크립트가 채우는 값은 누락될 수 있으며 해당 후보를 검증합니다. Bright Data 사용으로 기록하지 않습니다. |
| 기존 피드/Chrome 수집기 | 해당 스크립트의 별도 실행 조건 | 과거 데이터와 기존 파서를 유지하는 경로입니다. 공통 수집기와 실행 옵션·전송 정책이 동일하지 않습니다. |

2026-09-21 초기 점검에서는 zone이 없었으나 이후 사용자가 설정하여 실제 Bright Data 카드 원문 수집이 가능해졌습니다.
하나카드 EUC-KR 원문은 raw 바이트를 문자셋에 따라 디코딩하며, 렌더링된 현대카드의 추가 속성도 보존하여 추출합니다.
현 실행 결과는 보고서의 `transport`, `request_count`, `accepted_count`, 카드사별 결과와 URL별 근거를 확인하세요.

요청 상한은 `--limit`, 동시 요청 수는 `--concurrency`(최대 20)로 제한합니다. 카드사별 연속 실패 중단 기준은 `--failure-threshold`로 설정합니다.
인증·권한·할당량 등 실행 전체에 영향을 주는 오류는 반복 요청을 계속하지 않고 중단 사유로 기록합니다.
일부 URL은 전송 업체의 KYC 요구로 읽지 못할 수 있습니다. 이 오류는 키 인증 오류나 카드 원문 수집 성공으로 처리하지 않습니다.
카드사별 연속 실패로 건너뛴 요청도 실패한 요청이나 성공한 요청과 구분합니다.
캐시를 사용한 경우 새 네트워크 요청과 구분하고 **원래 수집 시각**을 보존합니다.

### Bright Data와 접근 조건

Bright Data는 사용자가 선택할 수 있는 공개 원문 수집 수단입니다. 이전 문서의
“명시적 robots Allow가 있는 경로만 전역 허용”, “Bright Data를 사용하지 않음”을 현재 공통 수집기의 정책으로 읽으면 안 됩니다.
기존 개별 수집기에 남아 있는 `robotsVerdict` 검사는 그 수집기의 구현입니다.

자동 접근 안내, 서비스 이용 조건, 저작권 등은 대상 사이트와 용도에 맞게 확인해야 합니다.
Bright Data 이용이나 공개 URL이라는 사실만으로 재이용 권한이 생기지는 않습니다.
현재 수집 범위는 로그인 없이 공개된 상품 정보이며 계정·개인 거래·로그인 세션 자료를 요청하지 않습니다.
접근 불가나 불완전한 추출은 보고서에 남기고, 원문을 확인한 것처럼 수집일을 올리지 않습니다.

## 카드사별 공식 진입점과 파서

아래는 수집·파서의 근거가 되는 공식 경로입니다. 모든 상품을 확보했다거나 현재 모든 경로에 접근할 수 있다는 뜻은 아닙니다.
실제 저장 카드 수와 실행 상태는 `data/cards.json` 및 `data/collection-report.json`을 기준으로 합니다.

| 카드사 | 공식 진입점·경로 | 확인할 점 |
| --- | --- | --- |
| 우리카드 | `https://pc.wooricard.com/sitemap.xml`, `/ai-data/card_{n}.html` | 공개 상품 피드의 JSON-LD·표에서 추출합니다. 잘린 금액이나 오탈자를 추측 복원하지 않습니다. |
| 현대카드 | `https://www.hyundaicard.com/cpc/cr/CPCCR0101_01.hc`, 상세 `/cpc/cr/CPCCR0201_01.hc?cardWcd=…` | 렌더링·접근 조건에 따라 본문이 달라질 수 있습니다. 주차 등 혜택의 “무료”를 연회비 없음으로 읽지 않습니다. |
| 신한카드 | `https://www.shinhancard.com/pconts/html/card/…`, 상세 `/pconts/html/card/apply/…` | 혜택 본문은 읽혀도 연회비가 `{{…}}` 템플릿으로 남을 수 있습니다. HTML 취득과 연회비 확인을 구분합니다. |
| KB국민·삼성·하나·롯데·NH농협·BC카드 | `data/issuers.json`의 공식 도메인과 `data/official-seeds.json`의 조사한 URL | 진입 URL 확보, 원문 취득, 파서 검증, 정본 반영은 각각 별개 상태입니다. 미수집을 상품이나 혜택이 없다는 뜻으로 쓰지 않습니다. |

`issuers.json`의 과거 `status_reason`이나 `coverage_note`는 이전 조사 설명일 수 있습니다.
실행 보고서가 있으면 최근 시도 결과를 우선 보고, 보고서가 없으면 이번 실행의 성공·실패는 **미확인**으로 표시합니다.
특정 카드사의 과거 접근 실패를 영구적인 수집 불가능 판정으로 고정하지 않습니다.

### 알려진 추출 오류와 처리

- `16,000원`처럼 보여야 할 금액이 `16,0`으로 잘린 경우, 추측해서 16,000으로 채우지 않습니다.
- 연회비에는 본인·가족·브랜드별 금액과 기본·제휴 연회비가 섞일 수 있습니다. 무관한 최저 숫자나 “무료” 문구를 가져오지 않습니다.
- `누적 이용금액`과 `전월 이용실적`은 다른 조건입니다. 전월이라는 근거가 없는 누적 조건을 전월실적으로 바꾸지 않습니다.
- 할인 대상 이용금액 한도와 실제 할인액 한도를 구분합니다. 단위를 모르는 금액은 피킹률 분자에 넣지 않습니다.
- 동적 템플릿이나 소프트 404를 정상 상품 정보로 취급하지 않습니다. 기존 카드보다 핵심 값·혜택 항목이 사라지는 후보는 보존 대신 교체하지 않습니다.

관련 회귀 검증은 `tests/collect.test.mjs`, `tests/rendered.test.mjs`, `tests/rendered-shinhan.test.mjs`와 공통 수집기 테스트에 있습니다.
회귀 테스트 통과만으로 모든 상품 약관을 대조했다고 표시하지 않습니다.

## 기록과 보존

| 파일 | 역할 |
| --- | --- |
| `cards.json` | 검증을 통과해 수록된 상품 정보. 각 카드에 실제 원문 URL·수집일·검수 상태가 있습니다. |
| `collection-report.json` | 실행 시각·전송 방식·요청 수·카드사별 시도/성공/실패·갱신/이전 유지 수입니다. |
| `collection-evidence.json` | URL별 시도 결과, 확보한 응답의 시각·SHA-256·바이트 수, 추출·검증 실패 사유입니다. 응답을 못 받은 실패에는 해시가 없을 수 있습니다. |
| 저장소 밖 원문 캐시 | 재검증용 HTML과 캐시 메타데이터입니다. 커밋·정적 사이트 배포 대상이 아닙니다. |

응답 해시는 동일한 바이트인지 확인하는 근거입니다. 카드 조건의 정확성·법적 효력이나 원문 저자의 진위를 보증하는 값이 아닙니다.
`generated_at`은 파일 또는 보고서 생성 시각이며, 모든 카드가 그날 재수집됐다는 뜻이 아닙니다.
기존 데이터를 유지한 카드의 `source.retrieved_at`은 원래 날짜로 남겨야 합니다.

## 기간 행사

세금 납부 무이자·부분무이자·캐시백 등 기간 행사는 `data/card-events.json`에서 따로 관리합니다.
카드사, 공식 URL, 시작일·종료일, 확인일, 요약과 적용 조건을 저장합니다.
대상 카드 제외, 신청 여부, 납부 채널, 금액 조건, 고객 부담 회차를 일반적인 “무이자 혜택”으로 축약하지 않습니다.

화면은 현재 한국 날짜와 행사 기간을 대조합니다. “기간상 진행 중”은 조기 종료·변경까지 실시간 확인한 결과가 아닙니다.
모든 저장 행사가 만료됐으면 현재 진행 중인 저장 행사가 없다고 표시합니다. 카드사에 아무 행사도 없다는 결론은 내리지 않습니다.
기간 미확인과 시행 예정도 진행 중 행사에서 분리합니다.

## 공식 상품을 추가하는 방법

1. 카드사 공식 도메인의 실제 상품 URL을 확보하고 카드 유형을 확인합니다.
2. 새 수집 대상이면 `official-seeds.json`에 넣고 공식 도메인 등록과 파서를 점검합니다.
3. 실제 읽은 조건만 정본 후보에 넣습니다. 알 수 없는 값은 생략하고 0·`false`로 대체하지 않습니다.
4. 자동 결과는 `machine_extracted`로 둡니다. 사람이 원문을 대조한 경우에만 `human_reviewed`로 표시합니다.
5. `npm run validate`, `npm test`, 빌드 후 카드 상세의 근거 표시를 확인합니다.

수집 실행과 배포는 별개입니다. 로컬 또는 승인된 워크플로 실행 결과를 검토한 뒤 정본과 화면을 갱신합니다.

## 사용자 요청으로 복구한 이전 목록

2026-09-22 요청에 따라 사용자가 이미 보관하던 카드고릴라 기반 파일의 1,563개 항목과 사진을 복구했습니다. 외부 제3자 API에 새로 접속하지 않습니다. `archive-catalog.json`과 `site/archive-details/`는 기존 자료의 이력이며, 공식 원문 데이터인 `cards.json`과 분리합니다. 기존 수치/설명은 이전 기록이라는 표제 아래 표시하며 현재 연회비·실적·세금 필터나 피킹률에 사용하지 않습니다. 이전 `is_discon` 값은 당시 표시일 뿐 현재 발급 상태로 간주하지 않습니다.

발행사·종류·정규화 상품명이 유일하게 일치하는 경우 공식 항목을 우선 노출합니다. 중복/변형 등 식별이 불확실하면 별도 이전 항목을 유지합니다. 모든 원래 ID는 보존됩니다. 이전 사진을 공식 항목의 대체 이미지로 사용할 수 있으나 이미지 출처는 이전 파일로 유지합니다. 카드 원본 사진을 변조하지 않고 세로 이미지의 화면 표시만 회전합니다.
