# 데이터 출처 정책

## 원칙

1. **카드사 본인이 공개한 것만 쓴다.** 카드 정보의 1차 권원은 카드사다.
2. **기계 접근이 명시적으로 허용된 경로만 쓴다.** `robots.txt` 에 `Allow` 로 적혀 있거나
   `sitemap.xml` 에 등재된 경로만 요청한다.
3. **차단을 우회하지 않는다.** User-Agent 위장, 헤드리스 브라우저 스텔스 플러그인, 세션 쿠키 재사용,
   CAPTCHA 우회를 쓰지 않는다. 막혀 있으면 수집하지 않고 "미수록"으로 남긴다.
4. **제3자 카드 비교 서비스의 API 를 쓰지 않는다.** 비교 서비스가 자체 투자로 구축한 데이터베이스를
   대량으로 가져오는 것은 개별 사실의 저작물성과 별개로 문제가 된다
   (저작권법 제4장의2 데이터베이스제작자의 권리, 부정경쟁방지법 제2조 제1호 (파)목).
   이 저장소는 그런 경로를 아예 사용하지 않는다.
5. **값을 추측해서 채우지 않는다.** 원본에서 온전히 읽히지 않은 숫자는 필드를 비운다.

## 실제로 사용하는 소스

### 우리카드 — 기계판독 상품 페이지

| 항목 | 내용 |
| --- | --- |
| 진입점 | `https://pc.wooricard.com/sitemap.xml` |
| 수집 경로 | `https://pc.wooricard.com/ai-data/card_{n}.html` |
| robots 근거 | `https://pc.wooricard.com/robots.txt` 에 `Allow: /ai-data/` |
| 형식 | schema.org `CreditCard` JSON-LD + 정적 HTML (표·요약 목록) |
| 요청 간격 | 기본 1,000~1,500 ms, 순차 1건씩 |
| User-Agent | `kr-card-benefits-lab/0.1 (...; +저장소 URL)` — 위장하지 않음 |

우리카드는 이 경로를 사람이 보는 상품 페이지와 별도로, 기계가 읽기 쉬운 정적 HTML 로 제공하고
`robots.txt` 에서 명시적으로 허용하고 `sitemap.xml` 에 등재해 두었다. 수집기는 실행할 때마다
`robots.txt` 를 먼저 읽고 명시적 `Allow` 규칙이 확인되지 않으면 **즉시 중단한다**
(`scripts/collect-issuer-feed.mjs` 의 `robotsVerdict`).

### 이 소스의 알려진 품질 문제

원본 피드는 기계 생성물이며 텍스트가 손상된 곳이 있다. 예를 들어 통합 한도 표에서
`16,000원` 이 `16,0` 으로 잘려 있거나, `청구할인` 이 `정구할인` 으로, `통합 월 할인한도` 가
`통합 원 할인한도` 로 적혀 있는 사례가 관측된다.

그래서 수집기는

- 천단위 구분이 3자리로 끝나지 않는 금액(`16,0`)을 **버린다**.
- 손상된 산문 조건문(`※ ...`)을 데이터로 옮기지 **않는다**. 대신 항상 공식 상품 페이지를 링크한다.
- 값을 읽지 못하면 필드를 생략하고, 카드의 `confidence` 를 낮춘다.

즉 이 저장소의 빈 값은 "혜택이 없음"이 아니라 **"확인하지 못함"** 이다.

## 검토했지만 사용하지 않는 소스

| 카드사 | 확인 결과 | 판단 |
| --- | --- | --- |
| 신한카드 | `robots.txt` 는 `/pconts/html/card/` 허용. `sitemap.xml` 은 404. 상품 상세가 스크립트 렌더링. | 미수록 |
| 삼성카드 | `sitemap.xml` 에 상품 상세 없음(서비스 안내 위주). 지정 봇에만 일부 경로 허용. | 미수록 |
| 현대카드 | `robots.txt` 는 관대하나 실제 요청이 보호 계층에서 차단됨. | 미수록 (우회 안 함) |
| KB국민카드 | `sitemap.xml` 미제공. `/CRD/` 허용이지만 기계판독 형식 아님. | 미수록 |
| 하나카드 | `sitemap.xml` 에 상품 상세 URL 존재하나 본문이 스크립트 렌더링. | 미수록 |
| 롯데카드 | `robots.txt` 응답 불안정. 상품 상세 스크립트 렌더링. | 미수록 |
| NH농협카드 | `robots.txt` 리다이렉트. 기계판독 피드 없음. | 미수록 |
| BC카드 | 기계판독 상품 피드 미확인. | 미수록 |

`/ai-data/` 및 `/llms.txt` 경로는 여러 카드사에서 탐색했으나, 일부는 200 을 반환하면서도 실제로는
"페이지를 찾을 수 없습니다" 본문을 주는 소프트 404 였다. 그런 응답은 소스로 취급하지 않는다.

## 명시적 금지 소스

- 제3자 카드 비교 서비스·가계부 앱의 비공개/내부 API
- 그런 서비스의 이미지 CDN 을 통째로 미러링하는 행위
- "공개 웹에 보이니 긁어도 된다"는 전제의 전수 복제

`scripts/validate.mjs` 는 데이터에 이런 흔적이 섞이면 실패한다
(`FORBIDDEN_SOURCE_PATTERNS`). 도메인 화이트리스트는 `data/issuers.json` 의
`allowed_domains` 에서 관리하며, 카드사 본인 도메인만 등록한다.

## 미수록 카드사를 추가하는 방법

자동 크롤을 늘리는 대신 사람이 확인한 값을 PR 로 받는다.

1. 카드사 **공식 상품 페이지 URL** 을 확보한다 (검색 결과나 비교 사이트 링크가 아니라 카드사 도메인).
2. 그 페이지에 실제로 적혀 있는 값만 `data/cards.json` 에 추가한다.
3. `source.kind` 를 `issuer_official_page` 로, `review_status` 를 `human_reviewed` 로 둔다.
4. `data/issuers.json` 의 해당 카드사 `allowed_domains` 에 도메인이 있는지 확인한다.
5. `npm run validate && npm test` 를 통과시킨다.

## 갱신 주기

자동 스케줄 크롤을 걸지 않는다. 수집은 `workflow_dispatch` 또는 로컬 실행으로만 한다.
데이터 기준일은 `data/cards.json` 의 `generated_at` 과 각 카드의 `source.retrieved_at` 에 있다.
